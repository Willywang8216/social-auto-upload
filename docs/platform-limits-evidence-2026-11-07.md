### Critical exact source excerpts

- TikTok photo reference: “The post title. The maximum length for photo posts is **90 in UTF-16 runes**.” Description: “**4000 in UTF-16 runes**.”
- TikTok status: `publicaly_available_post_id` is a **list**; a post ID is returned only for public viewership after moderation approval. A private completion or inbox notification is not public delivery.
- Sociamonials reference: “CALL THIS BEFORE POSTING and use only profiles where **agent_can_publish_to is true**”; workspace storage exposes `max_upload_bytes`, available bytes, enforcement and pooling.
- Sociamonials: strict validation runs without creating a post. Unsupported approved captions/settings are review exceptions; they are not rewritten to fit a backup.

Read-only live checks at **2026-11-07 00:06 UTC** reconfirmed NW and SW's same TikTok mapping, Teaching's separate mapping, connected publish grants and no approval hold. Both contexts returned hosted video **1,073,741,824 bytes**, image **15,728,640 bytes**, and pooled available storage **2,955,575,983 bytes**. These are time-stamped observations, not permanent grants. Native creators exposed public privacy options and a 3,600-second allowance; the retained SAU 600-second compatibility cap is not raised. Account configuration is not proof that a public post was delivered.

## Resulting code decisions

1. Keep existing video byte/duration budgets and dynamic tightening. Do not adopt larger X/creator entitlements or app-only limits automatically.
2. Correct TikTok photo title/description counting across pre-queue validation and the publisher. Approved overflows fail before submission; video captions stay at 2,200 UTF-16 units.
3. Tighten TikTok image preparation to the documented-resolution-compatible 1080-pixel long-edge policy. Resize the whole frame, never crop or alter originals; increment preparation policy to `2026-11-07-v4`.
4. Keep the verified backup's stricter caps, exact grants, strict validation, persistent bounded retries and durable terminal notification requirements. Successful, private-completed, cancelled and unresolved history is not a retry queue.
5. Posting cadence is an operator policy, separate from provider request limits: live timezone and configured daily/gap rules govern shared-destination scheduling. No limit is raised by recovery.
